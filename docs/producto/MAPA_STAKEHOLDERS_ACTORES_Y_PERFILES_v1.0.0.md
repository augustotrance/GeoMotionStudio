## 1. Objeto

Consolidar las personas, organizaciones y participantes técnicos relevantes para GeoMotion Studio sin convertir segmentos de mercado, responsabilidades institucionales o nombres futuros en roles de autorización.

Este mapa interpreta y relaciona fuentes vigentes. No sustituye la Visión del Producto, no constituye nuevas autoridades y no define permisos.

## 2. Distinciones obligatorias

| Concepto | Uso en G4 | No significa |
|---|---|---|
| Stakeholder | Persona, grupo u organización afectada por el producto o capaz de influir en sus resultados | Usuario directo, actor del sistema o autoridad automática |
| Usuario | Persona que utiliza el producto o recibe valor directo de él | Organización, rol de autorización o identidad técnica |
| Perfil de usuario | Agrupación de necesidades y prioridades de personas usuarias | Cuenta, permiso o persona individual |
| Actor humano | Persona que interactúa con un comportamiento para alcanzar un resultado | Rol institucional por el solo nombre |
| Actor técnico | Sistema externo que participa en una interacción delimitada | Componente interno, proveedor elegido o autoridad |
| Responsabilidad institucional | Función asignada por la gobernanza vigente | Actor de producto o permiso técnico |

La misma persona puede ocupar más de una categoría en contextos distintos, pero cada actuación debe declarar cuál aplica.

## 6. Actor y perfil del primer incremento

El actor primario aprobado para `INI-GMS-0001` es `ACTR-GMS-0001`, correspondiente al perfil heredado `U-001` y aplicable también a personas de `U-002` a `U-006` y `U-009` cuando persiguen el mismo resultado.

Descripción operativa:

> Persona de nivel principiante o intermedio que necesita iniciar un proyecto geoespacial local, ver un contexto cartográfico y retomar posteriormente el trabajo sin crear una cuenta ni depender de servicios remotos.

La selección evita diseñar para una organización abstracta o para todos los perfiles simultáneamente. Los perfiles secundarios informan restricciones, pero no amplían el alcance del piloto.

## 7. Participación por etapa

| Momento | Participación mínima |
|---|---|
| Descubrimiento | Contrastar necesidad, lenguaje y resultado con representantes del perfil primario |
| Especificación | Revisar flujos, errores, accesibilidad y criterios observables |
| Preparación | Confirmar que pruebas y datos representan el contexto de uso |
| Verificación | Ejecutar controles técnicos y de experiencia separados |
| Aceptación | Presentar evidencia al decisor competente; la opinión de usuario informa, no sustituye el acto |

## 8. Restricciones preservadas

- `Admin`, `AI` y `Usuario` continúan como hipótesis futuras y no son roles vigentes.
- `AI` solo puede aparecer como nombre heredado o literal de producto; la capacidad se denomina Inteligencia Artificial (IA).
- No se definen cuentas, permisos ni jerarquías de autorización en G4.
- No se constituye ningún participante institucional nuevo.
- Ningún actor técnico, proveedor o agente obtiene autoridad por su naturaleza.
- Este documento no crea una SPEC ni autoriza implementación.
