## 1. Contexto

El piloto exige guardar y reabrir localmente sin cuenta ni servicio remoto. La plataforma podrá ejecutarse en distintos entornos, y G7 todavía debe seleccionar su fundación ejecutable. El dominio no debe quedar atado anticipadamente a una API de navegador, sistema de archivos, base de datos embebida o formato físico.

## 2. Problema

Debe establecerse la frontera entre Project y el mecanismo concreto de almacenamiento de modo que el comportamiento de guardado, lectura, selección y confirmación pueda especificarse y probarse sin elegir todavía un backend.

## 3. Restricciones

- Project conserva la responsabilidad de persistencia definida en DOC-002.
- El recorrido no depende de un servicio remoto.
- La infraestructura no adquiere ownership del Project.
- El guardado solo puede declararse exitoso tras confirmación inequívoca.
- Un fallo preserva el último documento válido.
- G5 no adopta código ni tecnología.

## 4. Alternativas evaluadas

### A. Acceso directo desde Project a una API concreta

Reduce abstracciones iniciales, pero acopla dominio y plataforma, dificulta pruebas y vuelve costosa la sustitución. Se descarta.

### B. Servicio global genérico de almacenamiento

Puede reutilizarse, pero diluye las garantías específicas del Project Document y favorece contratos demasiado amplios. Se descarta como contrato de dominio.

### C. Puerto propiedad de Project con adaptador de infraestructura sustituible

Project publica el contrato mínimo y la infraestructura lo implementa para el entorno seleccionado. Conserva invariantes y permite cambiar backend. Se adopta.

## 5. Decisión adoptada

La persistencia local del Project Document se realizará mediante `CTR-GMS-PRJ-003`, un puerto propiedad de Project e implementado por un adaptador de infraestructura sustituible.

El puerto ofrecerá conceptualmente:

- selección o recepción de un localizador opaco;
- guardado atómico desde la perspectiva del dominio;
- lectura;
- comprobación de existencia cuando corresponda; y
- resultados tipados de éxito o error.

El localizador físico no formará parte de `projectId` ni se incluirá obligatoriamente en el Project Document. DOC-020 fija las garantías de atomicidad, respaldo y recuperación aprobadas para incorporación; la elección del backend y del mecanismo material permanece en G7.

## 6. Justificación

La decisión conserva independencia tecnológica, encapsula permisos y particularidades de plataforma, favorece pruebas de contrato y permite que el dominio exija garantías sin depender de cómo se materializan.

## 7. Consecuencias

### Beneficios

- Backend sustituible.
- Project permanece independiente de navegador o sistema operativo.
- Errores y confirmación poseen semántica uniforme.
- Las pruebas pueden usar adaptadores controlados.

### Costes y límites

- Debe implementarse y verificarse al menos un adaptador en G7.
- La selección de G7 deberá satisfacer la matriz de compatibilidad y los perfiles de permisos aprobados para incorporación en DOC-020.
- La semántica atómica debe probarse, no presumirse.

### Riesgos controlados

- Un puerto demasiado genérico perdería garantías: se limita al Project Document.
- Un adaptador puede incumplir atomicidad: G7 debe materializar y verificar las garantías `REL-G6-*` de DOC-020.
