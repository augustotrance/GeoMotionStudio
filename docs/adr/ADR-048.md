## 1. Contexto

DOC-004 fija Node.js, un gestor único, un monorepo y versiones controladas. El corte G6 carece de configuración raíz y el único lockfile pertenece al spike no adoptado. G7 debe permitir una instalación limpia reproducible.

Al 8 de septiembre de 2026, Node 24.20.0 es la versión Latest LTS; Node 26 continúa en estado Current. pnpm 12 es la línea vigente y 12.3.4 es la versión estable publicada.

## 2. Alternativas

### A. Node 26 Current

Se descarta para la línea base inicial porque Node recomienda LTS para aplicaciones de producción y el beneficio del corte Current no compensa su menor estabilidad temporal.

### B. Node 22 LTS

Es compatible, pero su horizonte de soporte es menor que Node 24 y no existe una dependencia heredada que obligue a conservarlo.

### C. Node 24.20.0 LTS

Se adopta por soporte vigente, compatibilidad con pnpm 12, Vite 8, Vitest 5 y Playwright, y horizonte razonable.

### D. npm o Yarn como gestor

Ambos podrían administrar workspaces. pnpm ofrece lockfile, aislamiento, control de scripts, licencias y SBOM en una sola herramienta y ya existe conocimiento histórico no vinculante en el proyecto. Se adopta pnpm desde una evaluación nueva.

## 3. Decisión

1. Node.js `24.20.0` es el runtime exacto de desarrollo y CI.
2. pnpm `12.3.4` es el único gestor de paquetes.
3. La raíz declara `packageManager`, `engines`, versión de Node y un único workspace.
4. Existe un único `pnpm-lock.yaml` compartido.
5. Todas las dependencias directas usan versiones exactas.
6. La instalación normativa usa `pnpm install --frozen-lockfile`.
7. Los scripts de instalación de terceros permanecen denegados salvo allowlist expresa, revisada y versionada.
8. Los comandos normativos no usan `latest`, rangos, `npx`, `pnpx` ni descargas dinámicas.
9. CI y entorno local ejecutan las mismas órdenes.
10. Toda actualización de Node, pnpm o lockfile requiere cambio controlado, evidencia y revisión de compatibilidad.

## 4. Consecuencias

### Beneficios

- instalación determinista;
- un solo grafo de dependencias;
- control de scripts y supply chain;
- licencias y SBOM con el mismo gestor;
- comandos homogéneos; y
- base compatible con el monorepo institucional.

### Costes

- se exige instalar versiones exactas;
- el lockfile pasa a ser artefacto gobernado;
- las actualizaciones automáticas no se fusionan sin evidencia; y
- pnpm constituye una dependencia de ingeniería sustituible mediante ADR.

## 5. Verificación

- versión Node igual a `24.20.0`;
- versión pnpm igual a `12.3.4`;
- un solo lockfile;
- instalación congelada satisfactoria en copia limpia;
- segunda instalación sin cambios en el árbol;
- 100 % de dependencias directas exactas; y
- cero scripts de terceros ejecutados fuera de allowlist.
