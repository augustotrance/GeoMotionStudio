## 1. Contexto

DOC-019 define el modelo lógico del Project Document y exige validación automática, pero difiere codificación, extensión y lenguaje de schema. El documento es entrada no confiable y debe ser inspeccionable, versionable y migrable.

## 2. Alternativas

### A. Clase TypeScript como único contrato

Se descarta porque los tipos se eliminan en runtime y no validan datos externos.

### B. Formato binario

Se descarta para el piloto por menor inspeccionabilidad y complejidad de evolución sin beneficio demostrado.

### C. YAML

Se descarta por amplitud sintáctica, ambigüedades de tipos y parser adicional.

### D. JSON + JSON Schema Draft 2020-12

Se adopta por interoperabilidad, validación formal, herramientas maduras y correspondencia directa con el modelo aprobado.

## 3. Decisión

1. La representación física es JSON estricto codificado en UTF-8.
2. La extensión canónica es `.gms.json`.
3. El media type interno documentado es `application/vnd.geomotionstudio.project+json`; no se declara registro externo.
4. `documentType` es `geomotion-project`.
5. `formatVersion` inicial es el entero `1`.
6. El schema usa JSON Schema Draft 2020-12.
7. Ajv `8.20.0`, export específico 2020, valida en modo estricto.
8. Los objetos son cerrados con `additionalProperties: false` o `unevaluatedProperties: false` según composición.
9. JSON no admite comentarios, `NaN`, infinitos, funciones, referencias cíclicas ni claves duplicadas toleradas silenciosamente.
10. El schema cubre forma, tipos, límites, enums y UUID; una segunda fase valida referencias cruzadas e invariantes de dominio.
11. Un documento inválido nunca se activa parcialmente.
12. Todo cambio incompatible incrementa `formatVersion`, incorpora migración explícita y requiere actuación institucional.

## 4. Organización de schemas

Los schemas se ubican bajo una ruta gobernada y se dividen por propietario:

- envelope Project Document;
- fragmento Project;
- fragmento Scene;
- fragmento Map View; y
- tipos técnicos compartidos mínimos.

Project compone sin apropiarse de la semántica de Scene o Map. Los `$id` son estables, no dependen de una URL remota y se resuelven localmente.

## 5. Consecuencias

### Beneficios

- formato legible y diffable;
- validación independiente de TypeScript;
- schemas por ownership;
- fixtures positivos y adversos reutilizables; y
- migración versionada.

### Costes

- JSON no es el formato más compacto;
- deben controlarse tamaño y profundidad;
- la validación estructural no reemplaza invariantes; y
- Ajv queda como dependencia sustituible encapsulada en Infrastructure.

## 6. Verificación

- schema y meta-schema resuelven offline;
- todos los fixtures válidos pasan;
- todos los adversos fallan por la razón esperada;
- propiedades desconocidas se rechazan;
- límites de tamaño/profundidad se aplican antes de activar;
- round-trip conserva equivalencia lógica; y
- ninguna API de Ajv cruza el puerto.
