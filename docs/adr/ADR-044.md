## 1. Contexto

`INI-GMS-0001` define “local” como ausencia de dependencia remota y excluye cuentas, sincronización y servicios remotos. Sin una decisión explícita, una vista cartográfica basada exclusivamente en teselas o APIs remotas podría hacer imposible crear, reabrir y reconocer el proyecto sin conectividad.

## 2. Problema

Debe decidirse si el recorrido base puede depender de un proveedor remoto, si debe incorporar una alternativa local o si el mapa base será exclusivamente local.

## 3. Restricciones

- El Project Document se guarda y reabre sin servicio remoto.
- El piloto debe presentar una vista cartográfica base 2D.
- Map y dominio permanecen independientes del proveedor.
- Fuente, licencia y atribución deben aprobarse antes de la SPEC candidata.
- G5 no descarga, integra ni selecciona datasets.

## 4. Alternativas evaluadas

### A. Proveedor remoto obligatorio

Ofrece cartografía rica con poco empaquetado, pero contradice la ausencia de dependencia remota y vuelve frágil el recorrido. Se descarta.

### B. Proveedor remoto con recurso local de continuidad

Permite mejoras conectadas y garantiza el recorrido mínimo sin red. Conserva posibilidad de sustitución. Se adopta como arquitectura.

### C. Recurso exclusivamente local para todo uso futuro

Garantiza autonomía, pero impondría una restricción prematura a capacidades posteriores. Se descarta como regla permanente.

## 5. Decisión adoptada

El recorrido obligatorio de `INI-GMS-0001` dispondrá de al menos un `baseMapRef` resoluble sin requerir red, cuenta, token ni servicio remoto.

Los proveedores conectados podrán evaluarse como mejora posterior, pero no serán condición para crear, guardar, cerrar, reabrir y reconocer la Map View del piloto.

La fuente o dataset, su licencia, atribución, tamaño, actualización y comportamiento verificable se decidirán en G6. El acceso se realizará mediante `CTR-GMS-MAP-003`, sin filtrar tecnología al dominio.

## 6. Justificación

La alternativa adoptada satisface el significado aprobado de “local”, evita que un tercero controle el recorrido mínimo y mantiene abierta la evolución a cartografía conectada sin convertirla en dependencia estructural.

## 7. Consecuencias

### Beneficios

- El valor principal puede demostrarse sin red.
- Mayor reproducibilidad y control de pruebas.
- Sustitución de proveedor sin cambiar el Project Document.
- Errores de red no impiden abrir el Project.

### Costes y límites

- G6 debe seleccionar y registrar un recurso legalmente compatible.
- G7 debe empaquetar o hacer disponible ese recurso y verificar atribución.
- El recurso mínimo puede tener menor detalle que un proveedor conectado.

### Riesgos controlados

- Un recurso demasiado pesado afectaría distribución: G6 debe fijar presupuesto.
- Una licencia incompatible bloquearía G8: `TECH-G5-002` es condición previa expresa.
